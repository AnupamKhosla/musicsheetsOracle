# Contributing & Developer Guide

## Quick Start

```bash
git clone <repo-url>
cd musicsheetsOracle
cp .env.example .env   # fill in your MongoDB URI
npm install
cd frontend && npm install && cd ..
npm run start_dev       # backend :5050, frontend :3000
```

### Prerequisites
- **Node.js** v18+
- **MongoDB Atlas** cluster (free tier works) — set `ATLAS_URI` in `.env`

---

## Architecture

```
Primary:  Browser → musicsheets.site → Cloudflare (proxied) → VPS:443 → Nginx → :5050 → Express
Backup:   Browser → musicsheets.tail0c6a25.ts.net → Tailscale relay → (tunnel) → :5050 → Express
                                   ↓
                            MongoDB Atlas
```

Both URLs serve the same application. The backup URL keeps the origin IP hidden via Tailscale relay — no open inbound ports, no domain dependency.

### Stack
- **Backend**: Node.js/Express (ES modules)
- **Frontend**: React (Create React App)
- **Database**: MongoDB Atlas
- **Process Manager**: PM2 with ecosystem.config.json

## Infrastructure (Server Setup Reference)

This section documents every step needed to set up the VPS from scratch. Use as a migration guide when moving to a new provider.

### Cloudflare DNS

| Setting | Value |
|---------|-------|
| A Record | `musicsheets.site` → (VPS IP), proxied (orange cloud) |
| SSL/TLS | Full (Strict) |
| HTTPS | Always redirect to HTTPS |

### Nginx (Reverse Proxy)

- Listens on port 443 (SSL) and 80 (HTTP→HTTPS redirect)
- Proxies requests to `localhost:5050`
- Raw VPS IP serves a static welcome page (not the application)
- Install: `sudo apt install nginx nginx-extras`

### SSL (Let's Encrypt)

```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d musicsheets.site -d www.musicsheets.site
```

- Auto-renewal via systemd `certbot.timer`

### PM2 (Process Manager)

```bash
# Start the application
pm2 start ecosystem.config.json

# Persist process list for reboot recovery
pm2 save

# Enable systemd service (run as your user, NOT root)
pm2 startup               # follow the sudo command it prints
```

- `ecosystem.config.json` defines app name (`musicsheets`), port (`5050`), and max memory (`300M`)
- `pm2 save` writes state to `~/.pm2/dump.pm2`
- Systemd unit: `pm2-<user>.service` (auto-generated by `pm2 startup`)

### Tailscale Funnel (Backup URL)

```bash
# Install
curl -fsSL https://tailscale.com/install.sh | sh

# Join your tailnet
sudo tailscale up

# Set hostname for a clean URL
sudo tailscale set --hostname=oracle

# Expose the application (survives reboots via --bg)
sudo tailscale funnel --bg 5050
```

- URL format: `https://<hostname>.<tailnet-name>.ts.net`
- Let's Encrypt SSL provisioned automatically on first request
- Origin IP is hidden behind Tailscale relay infrastructure
- The `--bg` flag persists the funnel across reboots (restored by `tailscaled.service`)
- Systemd unit: `tailscaled.service` (created automatically by the Tailscale installer)

### Systemd Services

| Service | Purpose | Auto-created? |
|---------|---------|---------------|
| `tailscaled.service` | Tailscale daemon + funnel persistence | ✅ By Tailscale install |
| `pm2-<user>.service` | PM2 process restoration on boot | ✅ By `pm2 startup` |
| `nginx.service` | Reverse proxy | ✅ By Nginx install |
| `certbot.timer` | SSL certificate renewal | ✅ By Certbot install |

### Swap File

The 1GB RAM VPS requires swap for production frontend builds:

```bash
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### Security

| Measure | Details |
|---------|---------|
| **Origin IP hidden** | Cloudflare proxied A record + Tailscale relay termination |
| **No public SSH** | Port 22 closed via firewall; access only through Tailscale SSH or VPN |
| **Webhook validation** | HMAC-SHA256 with `WEBHOOK_SECRET` from `.env` |
| **Rate limiting** | *(planned — `express-rate-limit` not yet implemented)* |
| **MongoDB access** | Atlas IP whitelist restricts connections to VPS IP only |

### CI/CD Pipeline

```
GitHub push to master
  → POST /api/webhook (HMAC-validated)
  → Express spawns deploy.sh
  → deploy.sh:
      1. Acquire flock lock (prevents concurrent deployments)
      2. touch /tmp/musicsheets-maintenance (triggers maintenance UI)
      3. git pull --ff-only
      4. npm install (root)
      5. cd frontend && npm install --include=dev && npm run build
      6. Build fails → maintenance stays active, logs exposed via UI
      7. Build succeeds → remove flag, pm2 reload, release lock
```

During deployment, all URLs serve a maintenance page with live build logs. The webhook endpoint stays open to allow re-triggering after a failed deployment.

## How to Contribute

1. Fork the repository and create a feature branch
2. Make your changes
3. Run `npm test` to verify everything passes
4. Submit a Pull Request

### Areas Needing Help

**Hosting & Infrastructure**
- Sponsorship for VPS hosting or domain renewal helps keep the project free and accessible.

**Music Sheet Collections**
- If you have a collection of digital or scanned Indian classical music sheets (Hindustani or Carnatic), we want to archive them. Contact us or submit a pull request.

**Bhatkande Notation System**
- Currently the project uses a basic notation format. We need to add proper support for the Bhatkande notation system (used widely in Hindustani classical).

**Sheet Music Player Plugin**
- Looking for a web-based playback plugin that can render Indian music notation in the browser and play the notes/sargam. Open-source preferred, but paid plugins are also worth evaluating.

**Musicians & Teachers**
- Feature suggestions, notation corrections, and guidance on transcription conventions are invaluable. If you teach or perform Indian classical music, your input shapes how the sheets are presented.

### Code Conventions
- Use **ES modules** (`import`/`export`, never `require()`)
- No CommonJS (avoid `.cjs` files and `module.exports`)
- Keep secrets, IPs, and credentials out of committed files
- The pre-commit hook runs `gitleaks` automatically — fix any flagged secrets before committing

## Pre-commit Security Hook

This repository uses [gitleaks](https://github.com/gitleaks/gitleaks) to block accidental commits of API keys, passwords, or secrets.

```bash
brew install gitleaks          # macOS
# hooksPath is already configured to .githooks/
```

The hook runs automatically on `git commit`. To scan the full repository manually:

```bash
gitleaks detect --source . -v
```
